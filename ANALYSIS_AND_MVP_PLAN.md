# Анализ проекта Dimas SaaS MVP (быстрый подбор авто) и план финального продукта

Дата разбора: 2026-08-30. Источник: код репозитория + лог `python run_web.py`.

---

## 1. Что это сейчас

Веб-приложение на FastAPI (`run_web.py` → `app.web.main:app`): пользователь задаёт марку/модель и фильтры, бэкенд **синхронно** парсит Drom / Avito / auto.ru, нормализует карточки, считает «выгодность» и отдаёт HTML.

Параллельно в репозитории живут **несколько несвязанных входов**:

| Вход | Назначение | Статус |
|------|------------|--------|
| `run_web.py` + `app/web/main.py` | Рабочий веб-MVP | Используется, падает на `/search` |
| `app/web/modern_app.py` | «Современный» UI | Не подключён к `run_web.py` |
| `main.py` | Streamlit | Дубль |
| `app.py` / `backend.py` | Ещё один API | Битые импорты (см. `MODERNIZATION_REPORT.md`) |

Это не SaaS: нет пользователей, тарифов, очередей, кэша, фоновых задач. Это **прототип парсера + скоринг**.

## 2. Разбор лога запуска (Audi Q3, источники drom+avito+autoru, limit=20)

### 2.1. Что прошло успешно

- Uvicorn стартовал, БД SQLAlchemy инициализировалась.
- Drom: `https://auto.drom.ru/audi/q3/` → **20 карточек**, детали по каждой странице (HTTP 200).
- После фильтров осталось **6** из 20 (год 2018–2026, пробег, владельцы).
- Одна запись успела обновиться в SQLite (`Updated listing: ...933513383.html`).

### 2.2. Avito — живой, но бесполезный

```
AVITO SEARCH: https://www.avito.ru/moscow/avtomobili/audi/q3/
HTTP 403 → retry ~30s → HTTP 200
AVITO CARDS page=1 count=0
AVITO FOUND: 0
```

Причины:

1. Антибот: 403 даже с прокси.
2. После 200 **селекторы карточек не совпали** с HTML (SPA/брендовый URL `/brands/moscow/...`).
3. Один и тот же прокси крутится по кругу (`user435202:...@185.81.147.98:1206`) — ротация фиктивная.
4. Задержки 8–45 с делают поиск неприемлемо долгим.

### 2.3. auto.ru — таймаут

```
AUTO.RU SEARCH: https://auto.ru/cars/sale/audi/q3/
Page.goto: net::ERR_TIMED_OUT
wait until "networkidle"
AUTO.RU FOUND: 0
```

Проблемы URL и Playwright:

- Правильный каталог auto.ru обычно `https://auto.ru/{region}/cars/{brand}/{model}/used/`, не `/cars/sale/{brand}/{model}/`.
- `wait_until="networkidle"` на тяжёлом JS-сайте почти гарантирует timeout.
- Прокси + headless без stealth часто режутся.

### 2.4. Критический 500 (падает весь поиск)

После успешного скоринга 6 машин:

```
File app/web/main.py, line 385, in search_cars
    "fuel": car.fuel,
AttributeError: 'CarListing' object has no attribute 'fuel'
```

`CarListing` (`app/models/car_listing.py`) **не содержит поля `fuel`**. Есть `transmission`, `drive`, `body_type`. В ORM есть `fuel_type`, в форме поиска есть `fuel`, в шаблоне ожидается `fuel`. Pydantic v2 при `extra="allow"` **не даёт** произвольный `car.fuel` через `__getattr__`.

Итог: пользователь **не видит даже 6 машин с Drom**. Поиск ~2 минуты → 500.

## 3. Полный список ошибок и дыр

### P0 — ломает продукт

1. **Нет поля `fuel` в `CarListing`**, но оно читается в `search_cars` и в фильтрах (`if fuel and car.fuel`).
2. **Последовательный блокирующий парсинг** в POST `/search` (Drom детали по одной с sleep 0.6–4 с × 20 ≈ 40–70 с, потом Avito retry 30 с, потом Playwright timeout). HTTP 500 после этого — UX мёртвый.
3. **Avito: 0 объявлений** при 200 — сломанные селекторы / URL (`url_converter` ведёт на `/brands/...`).
4. **auto.ru: неверный SEARCH URL + `networkidle`**.
5. **Фильтры не уходят в URL площадок.** Drom всегда `/{brand}/{model}/` без года, пробега, региона, цены. Регион `moscow` в логе **не применялся** к Drom (карточки из Екатеринбурга, Твери, Иркутска…). Фильтрация только post-hoc → теряются релевантные лоты и тратится время на чужие регионы.
6. **Синхронный `HTTPClient` внутри async-эндпоинта** — блокирует event loop.

### P1 — данные и скоринг врут

7. Две модели авто: dataclass `Car` и Pydantic `CarListing` — разные поля (`source` vs `platform`, нет `fuel` / `image_url` в одном из них).
8. `DataNormalizer` не нормализует `fuel`, `platform`, `engine_volume` (может быть `None` при `float` в модели).
9. `owners_count` — property, ок; но фильтр `if car.owners_count` **отбрасывает** объявления без числа владельцев? Нет: `if car.owners_count and (...)` — если `owners is None`, фильтр **пропускает** машину. Если `owners=0` — тоже. Неконсистентно с UI «1–3 владельца».
10. Скоринг `MarketEngine` / `MarketAnalyzer` на выборке из **6 объявлений одного поиска** — «рыночная цена» статистически мусор.
11. `car.market_deviation` пишется в объект, но **не объявлено** в модели (живёт только из‑за extra).
12. `save_listing`: при update копирует `vars(listing)` включая SQLAlchemy state — хрупко.
13. `parsing_results` — глобальный dict в памяти процесса, ключ `brand_model`, гонки, нет TTL.

### P1 — антибот / инфраструктура

14. Прокси захардкожены/в логах **с логином и паролем** (утечка секретов).
15. Один прокси на Avito и auto.ru.
16. Нет Playwright stealth, cookies, капчи.
17. Drom sleep 1–4 с на карточку без пула и без параллелизма (осторожно, но медленно).
18. Нет `.env.example`, секреты не через Vault.

### P2 — продукт / UX

19. `ALL_REGIONS` в `main.py` **не передаётся** в шаблон `home()` — только brands/models. Регион в логе откуда-то пришёл (форма?), но список в коде мёртвый для главной.
20. Опечатки регионов: `kemorovo`, `elenista`, `majachkala`.
21. Дубль брендов / мёртвый `modern_app`.
22. Нет авторизации, избранного, уведомлений, экспорта в рабочем флоу (есть `app/exports/exporter.py` — не связан с web).
23. Нет пагинации, сортировки на клиенте кроме probability.
24. Поиск ~2 мин без прогресса (кроме логов сервера).
25. `limit=20` деталит **все 20** Drom до фильтра — зря.
26. Изображение-заглушка `/static/images/no-car-image.png` — нужно проверить наличие.

### P2 — качество кода

27. Нет тестов парсеров/фильтров/скоринга.
28. `on_event("startup")` устарел в FastAPI.
29. Три HTTP-клиента (общий, Avito, Playwright).
30. `backend.py` импорты без `app.parsers.`.
31. README пустой (`# Dimas_Saas-MVP-parcers`).
32. HTML дебаг (`data/drom_debug.html`, `avito_debug_1.html`) в репо.

### Юридическое / риск MVP

33. Парсинг Avito/auto.ru/Drom без официального API — ToS, блокировки, 403. Для коммерческого SaaS нужен **план B: партнёрские фиды / публичные API / ручной импорт**, иначе продукт нестабилен.

## 4. Что уже относительно хорошо

- Drom list+detail реально собирает карточки.
- Есть нормализатор цены/пробега, SQLite, скоринг-заготовка.
- Форма фильтров (год, пробег, владельцы, КПП, топливо, привод, кузов, регион).
- Идея продукта ясная: **не агрегатор объявлений, а ранжирование выгодных лотов**.

## 5. Целевой MVP: «быстрый подбор автомобиля»

### Ценность для пользователя

За 15–30 секунд получить **короткий список (5–20) лотов** под бюджет и регион, с понятным вердиктом: «ниже рынка / норма / дорого», ссылкой на объявление и ключевыми ТТХ. Не «спарсить весь интернет».

### Вне скоупа MVP (не делать сейчас)

- Личный кабинет, подписки, биллинг.
- Telegram-бот, мониторинг 24/7 (есть `app/services/monitor.py` — отложить).
- VIN-отчёты Автотеки (дорого, партнёрка — фаза 2).
- Мобильное приложение.
- Идеальный Avito при постоянных 403.

### Скоуп MVP (must)

1. Один веб-поток: форма → прогресс → результаты (без 500).
2. **Один стабильный источник в проде: Drom** + опционально auto.ru, если починен URL.
3. Фильтры **на стороне запроса к площадке** (год, цена, регион), затем уточнение locally.
4. Карточка: фото, цена, год, пробег, владельцы, город, КПП, ссылка, бейдж выгодности.
5. Поиск не блокирует UI: фон + polling **или** сразу list-страница Drom без 20 detail (detail — по клику / топ-N).
6. Кэш одинакового запроса 10–30 мин.
7. Ошибки источников **не валят** выдачу (partial success + баннер «Avito недоступен»).

### Should

- Параллельный asyncio / thread pool для detail топ-N.
- Нормальная модель `CarListing` (fuel, market_deviation, image_url).
- Экспорт CSV/Excel из экрана результатов.
- Сохранение истории поиска в SQLite (без аккаунтов — cookie/session id).

## 6. План работ до «окончательного» MVP

### Этап 0 — починить текущий прогон (1 день)

1. Добавить в `CarListing`: `fuel: Optional[str] = None`, `market_deviation: float = 0`.
2. В `DataNormalizer` прокинуть `fuel` / `fuel_type` / `platform`.
3. В `search_cars` читать `getattr(car, "fuel", None)` не нужно после фикса модели.
4. Обернуть сериализацию в try/except так, чтобы 500 не было.
5. Avito/auto.ru: при ошибке писать в `errors`, **не ждать retry 45 с** на критическом пути (timeout 8–12 с, 1 retry).
6. auto.ru: `wait_until="domcontentloaded"`, URL вида `https://auto.ru/moskva/cars/audi/q3/used/`.
7. Не логировать полный URL прокси с паролем.

**Критерий:** тот же запрос Audi Q3 отдаёт HTML с ≥1 карточкой Drom, статус 200.

### Этап 1 — скорость (2–3 дня)

1. Drom search: query-параметры года/цены если сайт их принимает; регион в path (`moscow.drom.ru` / `auto.drom.ru/moscow/...` — проверить актуально).
2. Сначала парсить **листинг** (цена, год, пробег, url, фото) → фильтр → **detail только для топ-10**.
3. `asyncio.to_thread` / semaphore 3 для detail.
4. Не ходить на Avito по умолчанию; чекбокс «ещё Avito (медленно, может 0)».
5. Индикатор: SSE или «ищем…» + job id.

**Критерий:** p95 поиска Drom-only < 25 с на 10 карточек.

### Этап 2 — качество подбора (2 дня)

1. Единая схема полей и словарь нормализации КПП/топлива/привода (ru ↔ enum).
2. Скоринг: не медиана 6 штук, а эвристика:
   - штраф за пробег выше медианы;
   - штраф за 3+ владельцев;
   - бонус за цену ниже медианы **этой выдачи** + пометка «оценка по текущей выборке, не рынок РФ».
3. Честный UI: «оценка по N объявлениям этой выдачи».
4. Дедуп по URL и грубо по (year, mileage±1500, price±2%).

**Критерий:** топ выдачи объясним человеку за 5 секунд.

### Этап 3 — продукт MVP (3–4 дня)

1. Один вход: `run_web.py` → только `app.web.main` (или только `modern_app`, второй удалить/не рекламировать).
2. Регионы в шаблон, починить опечатки.
3. Пустой README заменить инструкцией запуска, лимитами, дисклеймером парсинга.
4. `.env` для прокси, не коммитить секреты.
5. Страница результатов: сортировка цена/год/выгода, фильтры без нового парсинга.
6. Кнопка «открыть на площадке».
7. Health `/health`.
8. Минимум тестов: normalizer, фильтры, отсутствие AttributeError на dummy `CarListing`.

**Критерий:** новый человек поднимает `python run_web.py`, находит Camry/Q3, видит список, не видит traceback.

### Этап 4 — задел SaaS (после MVP, не блокирует)

- Очередь Celery/RQ, воркеры парсеров.
- Пользователь + 3 сохранённых поиска + email/TG «появилось дешевле».
- Официальные источники данных / ручной CSV.
- Биллинг.

## 7. Рекомендуемая архитектура MVP (просто)

```
UI (Jinja) → POST /search/jobs  → Job(id)
                ↓
         Worker (thread):
           Drom list → filter → detail top-N
           [optional Autoru]
         SQLite cache by hash(brand,model,filters)
                ↓
         GET /search/jobs/{id} → results.html
```

Парсеры возвращают **один** dict/схему. Скоринг — чистая функция от списка. Web не знает BeautifulSoup.

---

## 8. Приоритизация источников

| Источник | Сейчас | Для MVP |
|----------|--------|---------|
| Drom | Работает | **Основной** |
| Avito | 403 / 0 карточек | Выключен по умолчанию; отдельно R&D (Playwright+прокси-пул) |
| auto.ru | Timeout, кривой URL | Починить URL; если снова 0 — optional |

Без стабильного Drom продукта нет. Три площадки «для галочки» хуже одной рабочей.

---

## 9. Метрики готовности MVP

- Поиск Drom по популярной паре (Camry, Q3, Rio) → 200, ≥5 карточек, <30 с.
- Нет unhandled 500 на `/search`.
- Падение Avito/auto.ru не прячет Drom.
- Фильтр года/цены отсекает до detail.
- Нет паролей прокси в логах.
- README: запуск за 3 команды.

---

## 10. Вывод

Проект — рабочий **скелет** подбора авто, но текущий прогон **не доводит результат до браузера** из‑за `CarListing.fuel` при уже найденных 6 лотах. Avito и auto.ru в этом логе дали 0. Скорость и фильтры «после парсинга» не соответствуют обещанию «быстрого подбора».

Финальный MVP: **Drom-first, быстрый листинг, честный скоринг по выборке, устойчивость к мёртвым источникам, одно приложение, починенная модель данных.** Остальное — следующая версия SaaS.
